# Mercato & budget — Implementation Plan

> **For agentic workers:** use the scoped task contract supplied by the coordinator; implement and verify each owned component without modifying another worker's files.

**Goal:** give each club a private recruitment and investment workbook, separating preparation from executed Classic transactions.

**Architecture:** existing FastAPI/SQLite manager stores plus a React page in Piloter le club. No new dependencies, game credentials, autonomous market writes or global market scraping. Manual observations remain explicitly dated and incomplete when inputs are missing. This implements the recruitment criteria accepted by the user on 31 October; routine design choices are delegated to the implementer.

**Tech Stack:** existing Python/Pydantic/FastAPI and React/TypeScript.

## Contract

- New `server/market.py`, `register_market(app, store, auth, require_team)`. Private club-only KV `market:<team_id>` using atomic optimistic revisions.
- GET `/api/market?team_id=...`: `{revision, updated_at, plan, candidates, investments, analysis}`.
- POST `/api/market`: `{team_id,expected_revision,plan,candidates,investments}`; validate, save, return same GET document. 409 preserves previous document. POST `/api/market/analyze` accepts same body and returns `{analysis}` without saving; revision need not gate a read-only analysis.
- plan: `cash`, `weekly_income`, `weekly_expenses`, `reserve`, `committed_bids` (nullable nonnegative finite monetary numbers), `complete` boolean, `observed_at` nullable ISO timestamp with timezone. Four-week horizon fixed and visible. Expenses include all current recurring costs; commitments exclude costs already debited. Unknown values never default to zero. Defaults null/false.
- candidates: max 50, each `{id,name,classic_id,role,age,price,weekly_salary,fees,skills,notes,status}`. IDs 32 lowercase hex; name max100; classic_id nullable positive decimal string (max15); role one of existing nine French domain role names; age nullable integer16..60; monetary fields nullable; skills all ten nullable finite0..21; notes max1000; status `watch|shortlist|dismissed`. Candidate salary is additional gross recurring cost, no assumed replacement savings. Default fees null. No external URL accepted; construct only official Classic links from validated IDs.
- investments: max20, `{id,name,initial_cost,weekly_cost,notes}`; monetary values nullable, same ID/name/notes limits. Each is an independent scenario, never assume all projects are purchased or sunk costs unpaid.
- analysis: backend supplies exact JSON contract promptly to frontend worker. Must include base four-week projection, conservative purchase ceiling constrained by both immediate cash and four-week cash after reserve/commitments, explicit missing fields/warnings, independent candidate and investment scenarios, and candidate-versus-current-squad role comparison with missing coverage disclosed. A positive projection is not an official game prediction or authorization. Partial or undated/unconfirmed budgets never show a green affordable recommendation. No negative cash normalized to zero before exposing deficit.

## Review focus

1. Cash available now can be lower than a projected surplus; both cap the bid.
2. Unknown salary/fees/expenses or missing timestamp must block a conclusive affordability label.
3. Candidate indices are local role comparisons; missing skills and unavailable squad observations must remain unknown.
4. Stale saves and late responses must never overwrite another manager/club or an unsaved draft.
5. No saved candidate or hypothetical investment is a submitted game order; no sensitive or private account data enters the public repository.
